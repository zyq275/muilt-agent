## 1. 引言

### 1.1 文档目的

本文档对「探渊」多智能体数据分析系统进行完整、明确的需求定义，作为设计、开发、测试、验收的唯一权威依据。文档只描述**功能与行为**，不涉及任何技术实现细节（技术方案见《技术设计文档》）。

### 1.2 适用范围

| 读者 | 用途 |
| --- | --- |

**系统范围外（本版不包含，见第 13 章路线图）**：内网完全离线部署、会话持久化与断点续跑、多用户账号鉴权体系。

## 2. 产品概述

### 2.1 背景与痛点

企业在日常经营中需要频繁产出各类分析报告（行业研究、竞品分析、市场调研、数据周报月报、政策解读等）。传统方式存在以下痛点：

1. **系统割裂**：查一份报告要在数据库、互联网、内部文档库等多个系统间反复切换；
2. **效率低下**：信息需手动整理汇总，耗时久、重复劳动多、易出错；
3. **协作不安全**：多人协作时数据缺乏隔离，存在越权与串扰风险。

### 2.2 产品定位

**探渊**是一款**多 AI 代理（Agent）协同的自动化数据分析平台**：用户以自然语言下达一句指令，系统自动拆解任务、调度多个专业智能体分工协作，从多源渠道汇总信息，最终自动生成结构化的数据分析报告（PDF）。

> 产品定位为**通用数据分析平台**，首个落地垂直场景为**医药行业**（以药品、库存、销售数据为示例数据模型），架构可复制到其他行业。

### 2.3 建设目标

1. **一句话出报告**：自然语言指令 → 自动规划 → 多智能体协同 → 自动生成报告；
2. **多源信息汇聚**：数据库（结构化）+ 全网（公开信息）+ 内部文档（非结构化知识）三路检索；
3. **过程透明可干预**：实时展示 AI 的思考、工具调用与中间结果，全程可追溯；
4. **企业级安全**：多用户并发数据隔离，互不干扰；
5. **结果有保障**：任务规划与反思，自我校验、多轮纠错。

### 2.4 成功指标（量化目标）

| 指标 | 目标值 |
| --- | --- |
| 任务受理响应 | 即时返回（不阻塞） |
| 报告内容完整度 | 不少于 1000 字 |
| 报告格式 | 支持 PDF（可含 Markdown 中间产物） |
| 反思纠错 | 首轮结果不达标时自动纠错，不直接返回错误结果 |
| 并发隔离 | 多用户同时使用时，数据与文件互不串扰 |

## 3. 术语定义

| 术语 | 说明 |
| --- | --- |
| 主智能体（主 Agent） | 系统调度中枢，负责接收任务、拆解规划、分发子任务、生成最终报告 |
| 子智能体（子 Agent） | 某一专业领域的执行者，如网络检索、数据库查询、内部文档检索 |
| 任务规划与反思 | 执行前自动拆解任务；执行后自我校验、发现不达标时多轮纠错优化 |
| 多源检索 | 数据库（结构化）、全网（公开）、内部文档（非结构化）三类信息渠道 |
| 内部文档库 | 企业私有文档/知识，经向量化后构建本地索引，可语义检索问答 |
| 会话 | 一次任务从提交到产出结果的全过程，具有唯一标识 |
| 工作目录 | 每次会话专属的隔离目录，存放生成的报告与上传文件 |

## 6. 功能性需求（FR）

> 优先级：**P0** = 必须实现（核心价值）；**P1** = 应当实现；**P2** = 可后续实现。

### 6.1 任务受理层

#### FR-001 任务提交与受理（P0）

- **描述**：用户以自然语言提交分析任务，系统受理并立即返回会话标识，任务在后台异步执行，不阻塞用户。
- **验收标准**：
  1. 提交任务后即时返回会话标识；
  2. 任务在后台执行，提交操作不被任务耗时阻塞。

#### FR-002 会话标识管理（P0）

- **描述**：每次任务生成唯一会话标识，贯穿"任务提交 → 文件上传 → 过程订阅 → 结果产出"全流程，作为数据隔离与结果定位的唯一键。
- **验收标准**：同一任务的各环节能通过会话标识关联；不同会话互不干扰。

### 6.2 智能编排层

#### FR-003 多智能体协同调度（P0）

- **描述**：由**主智能体**接收任务，智能拆解并分发给多个**子智能体**分工执行，汇总结果产出报告。
- **子智能体清单**（三个专业助手）：
  1. **网络检索助手**：检索互联网公开信息；
  2. **数据库查询助手**：查询结构化业务数据；
  3. **内部文档检索助手**：检索企业内部文档库。
- **业务规则**：
  1. 信息获取策略：公开/背景知识用网络检索；企业私有知识用内部文档检索；结构化业务数据用数据库查询；边界不明确时三种方式都尝试；
  2. 文件/报告的生成由主智能体完成，子智能体只负责检索；
  3. 子智能体不被告知文件生成位置。
- **验收标准**：复杂任务能被拆解并分发给多个子智能体并行/顺序执行，最终汇总成完整结果。

#### FR-004 任务规划与反思（P0）

- **描述**：系统在执行任务前自动拆解为可执行步骤（**规划**）；执行后对结果进行**双重校验**（**反思**）——① **内容性校验**（语义完整、结论成立）② **规范性硬校验**（篇幅/占位符/格式/数据源覆盖）；发现不达标时自动纠错并重试（**多轮纠错**），直至通过或达到重试上限（**默认 3 轮**）。
- **规范性硬校验项**：
  1. 篇幅：报告正文不少于 1000 字；
  2. 占位符：不含"待补充 / TODO / 等待任务"等未填充内容；
  3. 格式：用户要求 PDF 时，必须产出 PDF（先 Markdown 后 PDF）；
  4. 数据源：任务涉及的信息来源均已检索。
- **内容性校验项**：报告是否完整回答了用户问题、数据是否支撑结论、逻辑是否一致。
- **验收标准**：
  1. 首轮结果不达标时，系统自动纠错重试，而非直接返回错误结果；
  2. 最终结果通过全部校验；若多轮（默认 3 轮）仍未通过，返回当前最优结果并明确告知未达标原因。

### 6.3 数据检索层（三路多源）

#### FR-005 全网信息检索（P0）

- **描述**：网络检索助手从互联网检索**非内部**的公开信息，支持限定返回数量与主题类型。
- **业务规则**：同一问题至少从 2 个角度检索，最多检索 3 次，超过则停止。
- **验收标准**：能返回公开信息检索结果，检索次数受约束。

#### FR-006 结构化数据查询（P0）

- **描述**：数据库查询助手查询企业结构化业务数据，能力包括：查看可用数据表、预览表数据、执行自定义组合查询。
- **标准流程**：先确认有哪些表 → 预览表数据了解字段 → 执行精确查询。
- **验收标准**：能列出业务数据表、预览数据、按需返回查询结果；表不存在/无数据时返回友好提示。

#### FR-007 内部文档检索（P0）

- **描述**：内部文档检索助手通过**本地向量索引（Embedding + 向量数据库）**对企业私有文档/知识做语义检索，补齐互联网与数据库之外的企业专属知识。
- **验收标准**：能通过知识库助手检索并返回相关内容；保留检索到的原始信息用于报告生成。

### 6.4 报告生成层

#### FR-008 数据分析报告生成（P0）

- **描述**：主智能体汇总三路检索结果，自动生成结构化的**数据分析报告**。
- **支持格式**：**PDF**（最终交付物）；Markdown（可作 PDF 的中间产物）。
- **业务规则**：
  1. 生成 PDF 时，需先产出中间产物再转换为 PDF；
  2. 报告内容**不少于 1000 字**，丰富且全面；
  3. 严格按用户指令的报告类型生成，不得生成用户要求之外的格式；
  4. 用户未明确要求生成文件时，仅检索并直接反馈答案，不生成文件；
  5. 不得使用"等待任务完成"之类的占位内容生成报告；
  6. 汇报结果时**不发送文件路径**，仅告知"已成功创建"。
- **验收标准**：产出符合要求格式的报告文件，内容达标、无占位符。

#### FR-009 文件上传（P0）

- **描述**：支持用户上传一个或多个文件，保存到本次会话专属目录，供后续分析使用。
- **验收标准**：文件落盘至对应会话目录，支持多文件一次上传。

#### FR-010 上传文件解析（P0）

- **描述**：解析会话内上传的文件，支持常见格式（文本文档、Word、PDF、Excel 表格等）；对 Excel 提供行列数、预览与统计信息。
- **业务规则**：读取上传文件时，仅以文件名指代，不依赖目录前缀。
- **验收标准**：各支持格式能正确解析；文件不存在时返回明确错误。

### 6.5 平台支撑层

#### FR-011 执行过程可视化（P0）

- **描述**：实时向用户推送智能体执行过程，包括：会话创建、工具调用、子智能体调度、任务完成、错误等事件，全程可追溯。
- **验收标准**：用户能实时看到执行进度与中间步骤；不同会话的事件按会话隔离定向推送。

#### FR-012 多用户数据隔离（P0）

- **描述**：多用户并发操作时，各用户的数据、件文、执行过程相互隔离，互不串扰。
- **验收标准**：并发场景下，各会话只读写自己的目录与数据，无越权与串扰。

#### FR-013 文件浏览与下载（P1）

- **描述**：支持浏览会话产出的文件列表（含名称、大小、时间），并下载指定文件。
- **安全约束**：仅允许访问本次会话/结果目录下的文件，禁止越权访问。
- **验收标准**：能列出并下载合法文件；越权路径被拒绝。

#### FR-014 工作目录管理（P0）

- **描述**：每次会话创建专属工作目录，所有文件读写均限制在该目录内；上传文件自动装配到工作目录供分析。
- **验收标准**：文件读写被限制在会话工作目录内；上传文件正确出现在工作目录中。

---

### 6.6 前端界面（Web）

#### FR-015 Web 前端界面（P0）

- **描述**：提供单页 Web 应用作为统一交互入口，包含任务提交输入框、执行过程实时可视化（多智能体层级时间线）、文件上传 / 浏览 / 下载界面。
- **业务规则**：
  1. 执行过程按「主智能体 → 子智能体 → 工具」层级展示，用户可直观看到多智能体调度结构；
  2. 实时事件按会话定向推送，界面自动滚动刷新；
  3. 任务提交不阻塞，执行过程异步实时呈现。
- **验收标准**：用户能通过 Web 界面提交任务、实时看到执行层级过程、上传与下载文件。

## 7. 非功能性需求（NFR）

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-001 | 性能 | 任务受理即时响应；检索/生成不阻塞用户；文件上传采用流式处理避免大文件占满内存 |
| NFR-002 | 安全 | 文件访问隔离防越权；结构化数据查询防止误写与注入；敏感配置（密钥）不进入代码 |
| NFR-003 | 可靠性 | 智能体执行异常时不使服务崩溃并返回明确错误；会话结束及时释放资源 |
| NFR-004 | 可维护性 | 提示词与业务规则配置化；模块分层清晰；全链路可观测（日志记录关键步骤） |
| NFR-005 | 可扩展性 | 新增专业助手/数据源/工具应便捷（插件化），不改核心架构 |
| NFR-006 | 兼容性 | 全链路编码统一；中文与表格在报告中清晰呈现；运行环境明确 |

## 9. 数据需求

> 探渊为通用平台，以下为**首个落地场景（医药）的示例数据模型**，其他行业可替换对应业务数据。

### 9.1 结构化业务数据（医药示例）

| 实体 | 字段含义 |
| --- | --- |
| 药品信息 | 通用名、商品名、批准文号、规格、剂型、生产厂家、治疗领域、适应症说明 |
| 库存信息 | 所属药品、生产批号、库存数量、仓库位置、生产日期、有效期至 |
| 销售记录 | 所属药品、销售日期、销售数量、销售单价、销售总额、客户名称、销售区域、销售代表 |

> 三者关系：库存与销售均归属于某一药品。

### 9.2 内部文档库（非结构化）

企业私有文档/知识（如 SOP、政策文件、研究报告、合规资料），经分块 + 向量化后构建本地向量索引，通过知识库助手语义检索，作为第三类数据源。

### 9.3 文件存储约定

| 存储内容 | 说明 |
| --- | --- |
| 会话工作目录 | 每次会话专属，存放生成的报告与上传文件 |
| 上传暂存区 | 用户上传的原始文件 |

## 10. 业务规则汇总

| 编号 | 规则 |
| --- | --- |
| BR-01 | 主智能体必须先检索后生成，禁止使用占位符或空内容生成报告 |
| BR-02 | 报告生成仅由主智能体完成，子智能体只负责检索 |
| BR-03 | 网络检索：同一问题 ≥2 角度、≤3 次 |
| BR-04 | 数据库查询：先看表 → 预览 → 精确查询 |
| BR-05 | 内部文档检索：保留检索到的原始信息，不做过早概括 |
| BR-06 | 生成 PDF 必须先产出中间产物再转换 |
| BR-07 | 结果通知不含文件路径，仅告知"已成功创建" |
| BR-08 | 报告内容不少于 1000 字 |
| BR-09 | 所有文件读写仅限会话工作目录，禁止越界 |
| BR-10 | 任务执行前需规划步骤；执行后需反思校验，不达标则多轮纠错 |

---

## 11. 验收标准汇总

1. 提交自然语言任务 → 返回会话标识 → 实时推送执行过程（会话创建/工具调用/子智能体调度/结果）事件序列；
2. 纯问答任务：直接反馈答案，不生成文件；
3. 报告任务：产出符合格式（PDF）的报告，内容 ≥1000 字、无占位符；
4. 三路检索（数据库/全网/内部文档）均能返回有效信息并汇总；
5. 反思纠错：首轮不达标时能自动纠错，而非直接返回错误结果；
6. 多会话并发：数据、文件、执行过程按会话隔离，无串扰；
7. 越权路径访问（文件浏览/下载）被拒绝。
