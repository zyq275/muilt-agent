# 探渊 · 开发步骤文档（可执行版）

> 本文件是**拿来直接照着干**的操作手册：配合《探渊-需求规格说明书（PRD）》与《探渊-技术设计文档（TDD）》使用，指导开发者（或 AI 编码助手）从零分步搭建探渊系统。每一步都有：目标、依据、交付物、验收标准、可直接复制的 AI Prompt。

---

## 0. 前置准备

### 0.1 环境

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows（PDF 转换依赖本机 Microsoft Word） |
| Python | ≥ 3.12 |
| 包管理 | `uv` 或 `pip` |
| Node.js | ≥ 18（前端阶段 10 用 Vite 需要，`node -v` 检查） |
| 前端包管理 | npm（随 Node 附带） |
| 代码托管 | 初始化 git 仓库，每步 commit |

### 0.2 外部服务（开发前必须备齐）

| 服务 | 要准备 | 对应 TDD |
| --- | --- | --- |
| 大模型 | API Key（deepseek，按 TDD §2 选型） | §2 / §12 |
| 全网检索 | Tavily API Key | §2 / §12 |
| 本地知识库 | BGE Embedding 模型（本地路径或模型名）+ 语料目录 | §9.2 / §12 |

### 0.3 文档就位

将三份文档放入项目 `docs/` 目录，并在项目根目录建 `AGENTS.md` 指向它们：

```markdown

- 需求：docs/探渊-需求规格说明书（PRD）.md
- 技术：docs/探渊-技术设计文档（TDD）.md
- 步骤：docs/探渊-开发步骤文档.md（本文件，严格按阶段推进）
```

### 0.4 环境体检（第 1 课开场必做）

> 带做前先花 10-20 分钟逐项确认，谁没跑通现场解决，别带到课后。

在终端依次执行，全部无报错才算通过：

```bash
python --version      # 应 ≥ 3.12
node -v               # 应 ≥ 18（前端阶段 10 用 Vite 需要）

```

> 补充检查：PDF 转换依赖本机 Microsoft Word（阶段 4 用到，可到那时再确认）；外部服务（DeepSeek / Tavily / MySQL / BGE 模型）按 §0.2 逐项备齐。

## 1. 开发总原则（三条铁律）

1. **一次只做一个阶段**：AI 每阶段只收到本阶段的 prompt，不一次全丢；
2. **每阶段必须验收**：让 AI 贴运行输出或代码，确认通过才进下一步；
3. **每阶段 git commit**：出错可回退。

---

## 2. 用 CC 开发的标准五步（每个阶段都套用）

> 十一个阶段，动作都一样。记住这五步，不要每阶段重复想。

**第 1 步 · 让 CC 认识项目（只做一次）**：项目根目录建 `AGENTS.md`，指向三份文档（见 §0.3）。

**第 2 步 · 读文档**：打开本文件对应阶段，先看「依据 TDD」，翻到那一节，心里有数。

**第 3 步 · 发指令**：把该阶段「AI Prompt」原样复制给 CC。

**第 4 步 · 对照规格检查**：CC 写完别急着跑，对照 TDD 对应章节，看它有没有漏、有没有多写、有没有跑偏。这一步是学习发生的地方。

**第 5 步 · 验收 + commit**：跑该阶段「验收」命令，贴出输出确认通过，然后 `git commit`。

## 4. 各阶段详细步骤

### 阶段 0：项目骨架 + 日志 + 路径工具

- **目标**：搭好可运行的空壳。
- **交付物**：目录结构、`pyproject.toml`、`.env` 模板、`utils/logger_utils.py`、`utils/path_utils.py`、`main.py`。
- **验收**：`python -c "import utils.path_utils"` 不报错；`python main.py` 能启动一个空 FastAPI 应用。

**AI Prompt（复制用）**：

```
按 TDD §2、§3、§4.4、§12 完成阶段 0（项目骨架）：
1. 创建 TDD §3 的完整目录结构；
2. 写 pyproject.toml，依赖照抄 TDD §2 技术选型表；
3. 写 .env 模板，配置项照抄 TDD §12，密钥留空占位；
4. 写 utils/logger_utils.py（colorlog 彩色日志，含时间/文件/行号/级别/消息）；
5. 写 utils/path_utils.py，实现 TDD §4.4 描述的路径解析职责
   （虚拟路径清洗、上传目录处理、嵌套防护、越界校验）；
6. 写 main.py，启动一个空的 FastAPI 应用（端口 8000）。

完成后运行 `python main.py` 验证能启动，贴启动日志。
只做阶段 0，别做别的。
```

- **验收**：执行 init.sql 后，运行 `list_sql_tables()` 返回"可用的表：drugs,inventory,sales_records"。

**AI Prompt（复制用）**：

```
按 TDD §7.2、§9.1 完成阶段 1（数据库）：
```

- **验收**：各模块 import 不报错、`__main__` 测试入口能跑通最小调用；`build_knowledge_base.py` 能成功构建一次向量索引。

**AI Prompt（复制用）**：

```
按 TDD §4.2、§7.1、§7.3、§9.2 完成阶段 2（外部集成）：
1. 写 agent/llm.py：用 langchain-openai 的 init_chat_model 初始化 LLM
   （模型/端点/密钥从环境变量读取，按 TDD §2、§12）；
2. 写 tools/internet_search_tool.py：internet_search 工具，签名照抄 TDD §7.1，
   用 tavily-python 实现；

   签名与返回格式照抄 TDD §7.3，用 langchain-chroma + langchain-huggingface 实现；

每个模块加 __main__ 测试入口。完成后分别 import 验证不报错，并运行一次
```

### 阶段 5：编排层（★ 全系统最难，单独一步 + 人工 review）

- **目标**：主智能体组装 + 反思循环 + 三个子智能体配置。
- **交付物**：`agent/sub_agents/*.py`、`tools/reflect_check.py`、`agent/main_agent.py`。
- **验收**：代码 review 通过（重点看反思循环是否符合 TDD §5.2）。

**AI Prompt（复制用）**：

```
按 TDD §4.2、§5.2、§6 完成阶段 5（编排层）：
1. 写 agent/sub_agents/ 下三个子智能体配置（web_search / db_query / knowledge），
   每个含 name/description/system_prompt/tools，配置取自 load_prompt；
2. 写 tools/reflect_check.py 硬校验器，实现 TDD §5.2 的 H1~H4：

3. 写 agent/main_agent.py：
   - create_deep_agent 组装主智能体（三个子智能体 + 三个文件工具）；
   - run_deep_agent 实现反思循环，严格照抄 TDD §5.2 伪代码，
```

### 阶段 9：RAG 评估

- **目标**：量化验证内部知识库检索（RAG）的检索质量，回答"检索得准不准"。
- **交付物**：`eval/eval_questions.json`、`scripts/eval_rag.py`。
- **验收**：`eval_rag.py` 跑出检索命中率 ≥ 0.7；命中率不达标时能指出"建议调整分块参数或 embedding 模型"。

**AI Prompt（复制用）**：

```
按 TDD §7.3、§9.4 完成阶段 9（RAG 评估）：
1. 造 eval/eval_questions.json：10 条测试问题，每条含 query 和
   expected_source（期望能命中的来源文件名）；
2. 写 scripts/eval_rag.py：对每条 query 调用 search_knowledge_base，
   检查返回片段是否包含 expected_source，计算检索命中率 = 命中条数/总条数；
3. 打印每条问题的命中情况 + 总体命中率；命中率低于 0.7 时提示
   "建议调整分块参数或 embedding 模型"。

引入 RAGAS，对 query + 检索上下文 + 生成答案计算
Faithfulness / Answer Relevance / Context Precision / Context Recall 四个指标。

完成后运行 eval_rag.py，贴出每条命中情况与总体命中率。
只做阶段 9。
```

> **评估两层认知**：检索看"找没找对"（命中率 / Recall / Precision），生成看"答没答对、编没编造"（Faithfulness / Relevance）。本阶段只做检索层（不依赖 LLM 当裁判，最简单可解释），生成层评估作为进阶。

## 6. 常见坑与规避

| 坑 | 规避 |
| --- | --- |
| AI 一次写太多、跑偏 | 严格按阶段喂 prompt，一次一阶段 |
| AI 不贴运行结果就说"完成" | 每个 prompt 末尾都要求贴输出/代码 |
| Embedding 模型下载失败 / 路径不对 | 阶段 2 让学员确认 BGE 模型本地路径正确，或首次联网下载成功 |
| 反思循环写走样 | 阶段 5 单独拆出 + 人工 review 再往下 |
| 密钥硬编码进代码 | 阶段 8 专门检查一遍 |
